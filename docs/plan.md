# 路线图

主安装流程现已改为单 JAR drop-in：检查与预下载在运行中进行，helper 等整个 JVM 退出后安装。以下区分实现目标、既有证据与待验证事项，不保证首次扫描前最新。

## 1. 单 JAR 安装与生命周期

**本次目标：** companion 内嵌独立 helper；用户只需将一个 JAR 放进 mods。官方无配置新装 managed，已有配置保留，本地构建和开发环境保护。

**验收：** 无外部文件手动配置的真实首装；官方两版本退出后升级；原路径不变；无残留活 helper；开发保护贯穿子进程。结果见 [验证说明](verification.md)。

## 2. 重开竞态与恢复

**本次目标：** ctor 提前登记 lease，持锁检查 journal/安装标记；helper 每次修改重查 lease 与保护，冲突时拒绝混代加载。

**验收：** helper 各替换阶段与新 JVM 的可重复重叠测试，包括 helper 已退出、Mod ctor 才晚到的情况；中断时保留可恢复证据。不要将逐文件 rename 宣称为多文件原子事务。

## 3. 运行时与命令

**已有：** 游戏内轮询、提示和预下载；OP 4 正常停止与取消倒计时。

**已本地验收：** 只安装 updater 的真实 NeoForge 专服中，helper 重启授权、正常存档、整 JVM 重启、原世界重开、限额拒绝保活与正常关闭。使用测试构建，未测试完整 Folkways 包或真实玩家。

**后续：** 完整客户端重启需启动器账号/会话接入；当前不能重启集成服务器来冒充客户端更新。

## 4. 公开发行与自身更新

**已有：** Windows/Linux CI、可信主分支与版本 tag 发布、官方 API 摘要和成功 CI 身份；外部 seed 的 6.1→7.1 历史验证。

**本次验收：** 发行单 JAR 确实含可运行 helper，普通启动器流程通过，旧 seed 结果不作为新模式证明。首次手动安装仍是信任步骤。

## 5. Folkways 签名镜像

**已有：** 两源五渠道、五组件/按需下载、只读 fetch、离线签名、本地发布、不可变正式归档和 latest 指针；公开外链路径有实际验证。

**延期：** 公共自动签名、受限生产写入适配器和持久二进制归档。单 JAR 自身更新不依赖这些服务，也不会在缺少可信清单时替换 Folkways。

## 6. 长期可靠性

完整模组包/目标存档、Linux/Windows 真实安装故障矩阵、客户端启动器体验与断电耐久性逐步验收。当前外链归档不能保证上游删除后仍能获取二进制。
