# 路线图

这是可执行的阶段划分。已实现的机制与已上线的服务分开描述，实际验证边界见 [verification.md](verification.md)。

## 1. 明确启动与源约束

**已有：** 两个真实源仓库、五个发布 JAR、现有 CI 与加载器顺序核查；采用独立 Bootstrap，避免假设 ModLauncher SPI 在所有 JAR 打开前执行。

**验收：** 兼容版本源码可复查；源/tag/完整提交和五资产快照一致；没有凭空假定的 ZIP、签名索引或持久归档。

## 2. 安全更新核心

**已有：** 默认本地开发保护、选择模块、签名/摘要/范围校验、来源高水位、归属检查、pending 集合、逐文件事务恢复与有界缓存。

**验收：** 失败和中断不启动混代文件集；开发模式与人工编译不被覆盖；路径和并发故障按测试预期拒绝。

## 3. 运行时与专服生命周期

**已有：** 游戏内周期检查、提示、预下载；OP 4 命令、正常停止、专服 supervisor 重启、独占锁与持久 child 门禁。

**待验收：** 完整 Folkways 包及目标存档的升级/重新打开。临时专服的生命周期验证不替代完整客户端测试。

**后续：** 为具体客户端启动器提供安全的账号/会话接入，再考虑完整客户端重启。当前集成服务器拒绝 `/restart`。

## 4. 公开仓库、CI 与更新器自身更新

**已有/正在发布：** Windows/Linux 验证、可信主分支 nightly 与版本 tag 发布、官方 GitHub/CI 自更新身份、固定 seed 和独立 helper 交接。

**验收：** 首次公开 Actions 实际成功；六个资产与元数据一致；从上一官方版本实际升级；开发构建受保护；失败时已有版本可继续启动。seed 协议 v1 仍由用户手动安装，不做自替换。

## 5. Folkways 签名镜像与 OpenList

**已有：** 只读 fetch、离线签名、验证、发布计划、本地挂载目录发布；nightly 单套、正式版本不可变归档及 latest 指针。公开外链目录与 Release JAR 传输路径已有实际验证。

**待上线：** Folkways 自动签名发布、受限生产写入适配器和持久二进制归档。当前外链列表不等于这些能力已经上线。

**验收：** 可信来源、独立密钥管理、专用最小权限账号；真实后端上传任务完成、SHA256 读回、缓存失效、并发与中断恢复；非 nightly 二进制能在上游删除后仍取回。

## 6. 长期可靠性

后续优先级包括 Windows/Linux 的真实升级矩阵、启动器适配、异常恢复体验，以及断电与磁盘故障测试。只有测试完成后才扩展可靠性声明，不把逐文件 rename 描述成跨文件原子事务。
